# persistent-history

跨 `/reload`、`/new` 和新会话保留输入历史。

## 做什么

替换编辑器组件，把输入历史落到磁盘而不是只留在内存：

- 启动时读取最近 7 天内的历史文件，按 mtime 升序回放进编辑器历史
- 每次提交只追加到**当前会话自己的**文件
- 每个 pi 进程写独立文件，同目录下多个 pi 实例并发写入不冲突

存储位置：`<cwd>/.pi/input-history/<timestamp>_<pid>`，JSONL 格式，一行一条。

## 配置

无。7 天窗口硬编码在源码里。

## 调试

1. 输入几条命令，`ls .pi/input-history/` 应看到当前会话的文件
2. `/reload` 或 `/new` 后按上方向键，历史应该还在

## 陷阱

**每会话一个文件是有意设计。** 所有进程往同一个文件追加会产生并发写冲突。

**回放时跳过损坏行。** 单行 JSON 解析失败只跳过该行，不中断整个恢复过程。

**历史目录不可读时静默从头开始**，不报错也不提示。

**通过 `setEditorComponent` 实现**，所以与其他挂编辑器组件的扩展互斥——最后一个生效。本仓库的 notify-on-reply 为此改用 `onTerminalInput` 避开冲突，新增扩展时注意同样的取舍。

`.pi/input-history/` 已在本仓库 `.gitignore` 中。
